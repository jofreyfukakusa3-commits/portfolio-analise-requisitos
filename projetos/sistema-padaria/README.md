# Estudo de Caso: Levantamento de Requisitos para Sistema de Gestão de Padaria

## Sobre a experiência

Esta experiência representa meu início profissional na área de análise de requisitos.

Atuei como Analista de Requisitos no levantamento das necessidades para um sistema de gestão voltado às atividades de uma padaria.

Minha participação esteve concentrada na compreensão dos processos do negócio, identificação das necessidades dos usuários, registro das informações levantadas e documentação dos requisitos necessários para orientar a definição da solução.

Não participei do desenvolvimento ou da programação do sistema. Também não possuo o código-fonte, os documentos originais ou outros materiais internos do projeto.

Este estudo de caso foi elaborado para apresentar minha experiência profissional e os conhecimentos adquiridos durante essa atuação, sem divulgar informações confidenciais da empresa, dos usuários ou da solução original.

## Objetivo do levantamento

O levantamento teve como objetivo compreender o funcionamento da padaria e identificar quais funcionalidades seriam necessárias em um sistema de gestão capaz de apoiar suas atividades operacionais.

Durante o trabalho, foram analisadas necessidades relacionadas ao controle das informações, organização das rotinas e acompanhamento dos processos realizados no estabelecimento.

## Minha atuação

Minha atuação como Analista de Requisitos envolveu atividades como:

- Levantamento das necessidades apresentadas pelos responsáveis pelo negócio
- Entendimento das rotinas realizadas na padaria
- Identificação dos usuários envolvidos nos processos
- Análise dos problemas relatados pelos usuários
- Identificação das funcionalidades necessárias
- Registro dos requisitos funcionais
- Identificação inicial de regras de negócio
- Organização das informações levantadas
- Apoio na definição do funcionamento esperado da solução
- Comunicação das necessidades para a equipe responsável pelo sistema

## Processos analisados

Durante o levantamento, foram considerados processos relacionados a:

- Cadastro de produtos
- Controle de estoque
- Registro de vendas
- Gestão de encomendas
- Cadastro de clientes
- Cadastro de fornecedores
- Controle da produção
- Consulta de informações
- Emissão de relatórios gerenciais

## Necessidades identificadas

Entre as necessidades analisadas durante o levantamento estavam:

- Centralizar as informações utilizadas pela padaria
- Melhorar o controle dos produtos disponíveis
- Registrar as movimentações de estoque
- Organizar os pedidos e as encomendas dos clientes
- Acompanhar as atividades relacionadas à produção
- Manter o cadastro de clientes e fornecedores
- Facilitar a consulta das informações do negócio
- Apoiar o acompanhamento das vendas
- Disponibilizar informações para apoio à gestão

## Possíveis funcionalidades levantadas

A partir das necessidades identificadas, foram consideradas funcionalidades como:

- Cadastro e manutenção de produtos

## Exemplos de requisitos

### RF001: Cadastro de produtos

O sistema deverá permitir o cadastro de produtos comercializados pela padaria.

O cadastro poderá conter informações como nome do produto, categoria, unidade de medida, preço e situação do registro.

### RF002: Cadastro de clientes

O sistema deverá permitir o cadastro dos clientes da padaria para utilização em vendas e encomendas.

### RF003: Controle de estoque

O sistema deverá permitir o registro das entradas e saídas de produtos, possibilitando o acompanhamento da quantidade disponível em estoque.

### RF004: Registro de vendas

O sistema deverá permitir o registro das vendas realizadas, contendo os produtos, as quantidades e os valores envolvidos.

### RF005: Gestão de encomendas

O sistema deverá permitir o registro e o acompanhamento das encomendas realizadas pelos clientes.

### RF006: Cadastro de fornecedores

O sistema deverá permitir o cadastro dos fornecedores responsáveis pelo fornecimento de produtos e insumos.

### RF007: Relatórios gerenciais

O sistema deverá disponibilizar consultas e relatórios para apoio ao acompanhamento das vendas, do estoque e das encomendas.

## Exemplos de regras de negócio

### RN001: Quantidade em estoque

A quantidade disponível de um produto deverá ser atualizada sempre que houver uma entrada ou uma saída registrada.

### RN002: Produto ativo

Somente produtos ativos poderão ser utilizados em novos registros de venda ou encomenda.

### RN003: Dados obrigatórios

Os dados definidos como obrigatórios deverão ser preenchidos antes da conclusão de um cadastro.

### RN004: Registro de encomenda

Uma encomenda deverá possuir, no mínimo, a identificação do cliente, os produtos solicitados e a data prevista para entrega.

### RN005: Histórico das movimentações

As movimentações de estoque deverão permanecer registradas para consulta e rastreamento.

## Exemplo de história de usuário

### HU001: Registrar encomenda

Como atendente da padaria,  
quero registrar uma encomenda realizada por um cliente,  
para que o pedido possa ser acompanhado até sua entrega.

#### Critérios de aceite

1. O sistema deverá permitir selecionar ou cadastrar o cliente.
2. O sistema deverá permitir informar os produtos solicitados.
3. O sistema deverá permitir informar as quantidades.
4. O sistema deverá permitir informar a data prevista para entrega.
5. O sistema deverá registrar a situação da encomenda.
6. O sistema deverá impedir a conclusão do cadastro quando informações obrigatórias não estiverem preenchidas.
